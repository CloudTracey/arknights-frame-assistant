# 悬浮窗

## 使用与配置

悬浮窗是独立的无标题栏置顶窗口，显示功能名称与已配置的按键。首次使用默认隐藏，后续启动恢复上次的显示或隐藏状态；通过托盘的“显示/隐藏悬浮窗”或用户配置的全局快捷键切换，显示时托盘项打勾。默认左键穿透，按住右键拖动窗口中部移动位置，拖动边缘或角落调整大小；窗口没有标题栏和系统缩放边框。

“其他设置 → 显示”中的“悬浮窗设置”提供以下配置，点击应用或保存后生效。以下默认值及规范化规则以 `Constants.OverlayDefaults` 和对应 `NormalizeOverlay*` 方法为准。

| 配置 | 默认值 | 规则 |
|------|--------|------|
| 不透明度 `OverlayOpacity` | 85% | 取整并限制为 20–100；非数值回退默认值；整个窗口连同文字一起调整不透明度 |
| 背景色 `OverlayBackground` | `202020` | 六位十六进制 `RRGGBB`，统一转为大写；非法值回退默认值 |
| 显示快捷键 `FloatingWindowToggle` | 未绑定 | 属于独立的全局热键组，参与现有冲突检测；清空后仍可通过托盘操作 |
| 宽度 `OverlayWidth` | 500 逻辑像素 | 拖动保存，配置值限制为 1–3000，实际显示时保证容纳全部文字 |
| 高度 `OverlayHeight` | 300 逻辑像素 | 拖动保存，配置值限制为 1–2000，实际显示时保证容纳全部行；方案组切换时按内容重新计算 |
| 位置 `OverlayX` / `OverlayY` | 未设置 | 记录窗口左上角的屏幕物理坐标，允许负数；缺失或非法时使用 Gui 默认位置，再校正到显示器工作区 |
| 显示状态 `OverlayVisible` | `0`（隐藏） | 显示为 `1`、隐藏为 `0`，启动时恢复；仅首次初始化读取，设置窗口重建不会重新覆盖当前请求 |

外观、尺寸、位置和显示状态存于 `Settings.ini` 的 `[Main]`，快捷键存于 `[Hotkeys]`。所有写入通过 `SettingsService` 完成，并同步 Config 工作副本，防止随后应用设置时覆盖运行中保存的状态。正常完成显示/隐藏切换时保存显示请求；松开右键、隐藏和正常退出时保存位置及尺寸。显示前若屏幕布局发生变化，先校正位置再保存，使窗口保持在可操作的工作区。强制结束进程不会执行退出回调，最近一次已完成的写入仍保留。

## 创建与显示

`FloatingWindow.Init` 由 `GuiManager.Init` 调用，订阅设置、语言、方案组及热键总开关事件，并注册快捷键与右键交互。首次初始化读取 `OverlayVisible`，上次为显示时立即恢复窗口，否则延迟创建；重复初始化只同步托盘勾选。首次显示前不创建 Gui；显示/隐藏复用已有对象。设置保存、应用、取消、重置或语言变化时刷新已有窗口，即使窗口当前隐藏也会重建；从未打开过的窗口延迟到首次显示时读取最新配置。

`WantVisible` 表示请求状态，`IsVisible` 表示已经完成的显示状态。`Changing` 串行化创建与重建；期间收到的显示/隐藏请求在当前操作完成后统一执行。新 Gui 及其控件在创建成功后才发布到类字段。

创建方法返回局部窗口状态，由 `_AdoptWindow` 统一接管。重建时保留原 Gui 和控件引用，替换窗口完成创建与定位后才接管并销毁原窗口。创建或定位异常时清理替换窗口并记录日志，随后按 `WantVisible` 恢复原窗口的显示或隐藏状态并同步托盘；下一次应用设置或方案刷新会再次尝试重建。恢复的是旧内容，成功重建后才显示新配置。

该回退针对已有窗口的重建阶段。首次创建没有旧窗口可恢复；创建异常会清理已创建的临时 Gui、记录错误并向调用方抛出，不在定时器中自动重试。托盘勾选依据实际显示状态更新，后续显示请求可再次尝试创建。

## 透明度

沿用仓库内 AHK 官方文档 `docs/ahk_docs/lib/Gui.htm#ExOSD` 的 OSD 模式：普通 Gui 添加控件并完成布局后，先用 `Show("Hide ...")` 建立隐藏窗口的尺寸，再将 Gui 对象直接传入 `WinSetTransparent`，最后按请求显示。鼠标穿透通过 `WinSetExStyle("+0x20", guiObj)` 开启，右键操作由独立热键根据屏幕坐标命中悬浮窗区域。

隐藏窗口必须用 Gui 对象或纯整数 HWND 定位。`"ahk_id " hwnd` 仍是窗口搜索字符串，受隐藏窗口检测设置影响，不能等同于纯 HWND。

不手动预置 WS_EX_LAYERED、不调用 SetLayeredWindowAttributes、不强制重绘、不注册 Size 回调。

## 尺寸与交互

持久化宽高统一为 AHK Gui 逻辑像素。读取使用 `Gui.GetClientPos`，首次创建使用 `Gui.Show`。屏幕坐标和鼠标位移为物理像素；鼠标位移除以 `A_ScreenDPI / 96` 后参与尺寸计算。调整窗口时使用 `WinMove`，仅将逻辑宽高乘回 DPI 比例，X/Y 保持屏幕物理坐标。

AHK v2.0.26 的 `source/script_gui.cpp` 中 `GuiType::Move` 会缩放 X/Y/W/H 四个参数，与本地 Gui.Move 文档仅缩放宽高的说明不同，因此不使用 Gui.Move 定位。每次显示前检查显示器工作区，回收移出屏幕的窗口。

右键热键只启动一个 16 ms 定时器。每次回调最多进行一次几何更新；几何未改变时不操作窗口。松开右键、隐藏或正常退出时经 SettingsService 保存位置和尺寸，拖动期间不逐帧写盘。任务栏、菜单和按键录制期间不截获右键。

日志记录创建、显示、隐藏、快捷键注册和尺寸保存，便于区分绘制问题与状态问题。

列宽、文字高度通过 Text 控件首次自动定尺寸后的 GetPos 测量。字体使用 Metrics.FontFor 按当前语言选择。最小宽度为最长功能名列、最长按键列、列间距与两侧边距之和；最小高度为所有实测行高、行间距与上下边距之和。按键列使用实际测量宽度，功能名列吸收放大时的额外空间。

边距、列间距、最小行高、字号、拖动命中区域及刷新间隔是 FloatingWindow 中的命名设计参数。DPI 基准 96 和 WS_EX_TRANSPARENT 值属于平台约定；不作为内容尺寸的限制。配置默认值与尺寸上限集中在 Constants，3000×2000 逻辑像素是现有最大尺寸限制，正常内容最小尺寸优先于该限制。

文字颜色根据配置背景的相对亮度，从黑/白中选择对比度更高的一种。计算公式采用 [WCAG 对比度及相对亮度定义](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)，该选择针对配置背景色，不表示半透明合成后的画面满足某一对比度等级。

托盘通过唯一的“显示/隐藏悬浮窗”项切换状态，显示时打勾。勾选状态只根据完成后的 IsVisible 更新，托盘重建后重新同步。

`FloatingWindow.AddTrayItem` 统一添加托盘项并记录实际名称 `TrayItemText`。`LocaleChanged` 时按该名称重命名，勾选始终使用实际名称而不重新推导翻译。正常语言应用流程仍由 `GuiManager.Rebuild → Init` 重建整套菜单；显式名称同步也覆盖语言变化与菜单重建之间的状态。

## 当前方案

悬浮窗通过 HotkeyService.GetEnabledBindingIds 获取当前已启用方案的内置/自定义绑定标识，不自行维护另一套方案状态。HotkeyGroupChanged、HotkeyStateChanged 触发内容刷新。常规作战/快捷操作与卫戍协议互斥，自定义按键采用 HotkeyService.CustomProfiles 中已验证的生效组；全局自定义按键在两种方案中均显示。

这里的“已启用”表示属于当前方案组且已绑定，并非游戏焦点或关卡守卫等即时触发条件。悬浮窗不跟随游戏前后台自动隐藏，也不实时标记按键能否触发。内置按键按 `HotkeySchema.Items` 顺序显示，随后显示已绑定的启停热键和当前方案的自定义按键；不显示空绑定，自定义项还须有名称。没有任何可显示项时显示“当前没有已启用的按键”。

热键总开关关闭时隐藏游戏及自定义动作；SwitchHotkey 和悬浮窗切换键独立于该开关，仍显示已绑定项。

实际方案组变化时，窗口高度按当前显示行的实测高度、行间距和上下边距重新计算，不继承前一方案保存的高度。常规作战与快捷操作属于同一方案组，二者之间切页不触发高度重置。悬浮窗尚未创建时先记录适配请求，首次显示时再按当前内容计算高度。

游戏热键菜单项按当前名称重命名，不依赖菜单序号。设置页的按键录制通过 Config.AllHotkeys（来自 Schema）、SwitchHotkey 和自定义按键控件模式识别，普通输入框无需逐个加入排除清单。

“显示”页面分为两栏：左栏为原显示设置和顶部标签页管理，右栏为独立的悬浮窗设置、操作说明及特性。文本按列宽自动换行；底部按钮基准取基础功能提示与显示设置控件底部的最大值，避免翻译变长后覆盖按钮。
