## 问题反馈

* `2026-08-09`：删除计划任务后再次启用时出现 `(0x80070002) 系统找不到指定的文件`。原因是 Task Scheduler COM 返回普通 `Error`，错误码只包含在 `Message` 的 HRESULT 中，原实现只读取 `Error.Number`，把“任务不存在”误判为失败。已增加 HRESULT 低位错误码解析；最小复现由 RED 变为 GREEN，等待新测试 EXE 手工确认。
* `2026-08-09`：两次手动启动均无错误，审核查询未写入，但日志连续显示“计划任务已创建或更新”，未达到稳定状态不重写。初次修正根据导出 XML 接受 SID，但用户复测仍显示 `principal` 漂移；进一步读取 COM 发现它返回短用户名 `panyitong`，而不是 XML 中的 SID。现通过 `LookupAccountNameW` 把账户名、短用户名和 SID 统一解析为 SID 后比较，并细分主体字段日志；真实任务复现由 RED 变为 GREEN，等待 v2 EXE 确认“计划任务已匹配，跳过重写”。
