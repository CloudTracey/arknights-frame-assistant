## 集成测试

### 流程1：关卡外 4 键同按同松（主验证）

> 涉及模块：`hotkey_actions`、`hotkey_control`、`game_keys`、`logger`

> 前置：AFA 已启动、热键已启用、游戏窗口在前台、当前不在关卡界面（如主界面/结算界面）、`InLevelGuard` 开关开启（默认）

- [x] **操作**：按住 `a` + `s` + `w` + `d` 四个键（对应 Retreat / Skill / PauseSelect / GameSpeed 的默认绑定），保持约 0.5~1 秒，然后**同时松开**
- [x] **预期**：松开后无任何键卡住（角色不持续移动、不反复触发技能等）
- [x] **操作**：查看日志（`%AppData%\ArknightsFrameAssistant\PC\logs\`）中本次操作的透传记录
- [x] **预期**：四个键松开时**各出现一条** `透传 Up：key=a/s/w/d`，**不能有缺失**；同时四条 `透传 Down：key=a/s/w/d` 完整
- [x] **操作**：重复「同按 4 键 → 同时松开」10~20 次（四键同松是触发该 bug 的最高概率场景）
- [x] **预期**：每次都无卡键，日志中四条 Up 始终齐全

##### 异常路径

- [x] **异常**：若某次出现某键的 Up 缺失 → **预期**：该键被卡住；修复后此场景不应出现。一旦出现即为回归失败，记录下方问题反馈（本次未触发）

### 流程2：关卡外 2 键同按同松（低频场景）

> 涉及模块：同上

- [x] **操作**：任取两个拦截键（如 `a`+`d`）同按同松，重复 10~20 次
- [x] **预期**：两键的 `透传 Up` 均齐全，无卡键（用户反馈原 bug 偶发于 2 键同松）

### 流程3：关卡外单键按下松开（打字/操作不受影响）

> 涉及模块：`hotkey_actions`、`key_forward`

- [x] **操作**：关卡外单按 `s` 再松开
- [x] **预期**：日志出现 `透传 Down：key=s` 与 `透传 Up：key=s` 各一条，键不卡
- [x] **操作**：在任意非游戏窗口（如记事本）正常打字
- [x] **预期**：按键透传正常，无卡键、无重复输入（游戏外主热键不触发，Up 变体不放行、物理 up 正常透传）

### 流程4：关卡内功能正常（守卫放行路径回归）

> 涉及模块：`hotkey_actions`、`game_keys`

- [x] **操作**：进入任意关卡，按下绑定的技能键（默认 `s`）、撤退键（默认 `a`）
- [x] **预期**：功能正常触发（释放技能/撤退），松开后不卡键
- [x] **操作**：关卡内使用倍速切换（默认 `d`）、暂停选中（默认 `w`）
- [x] **预期**：功能正常，无卡键

### 流程5：卡键次生症状不复现

> 涉及模块：`key_forward`

> 说明：原 bug 的次生症状是——某键 Up 被吞后残留 `InterceptedKeys` 标志，导致**再次按下该键无 Down 日志**、松开才有 Up。修复后首轮 Up 不再被吞，不应出现此症状。

- [x] **操作**：在流程1的多次同松测试后，单按一次 `s`（该键曾在多次 4 键同松中被使用）
- [x] **预期**：日志有 `透传 Down：key=s`（不存在"按下无 Down"的残留标志症状）
