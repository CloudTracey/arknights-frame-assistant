> 涉及模块：`settings_service.ahk`、`webview_runtime.ahk`（本流程需临时改注册表，可跳过）

> **本轮决定：跳过 —— 未运行验证，仅代码审阅。**
> 原因：唯一验证途径是把 `pv` 改名，而该值同时是 WebView2 官方安装检测依据（`WebView2Loader.dll` 找运行时也走它），改名期间机器上所有 WebView2 应用都会"找不到运行时"，代价与收益不匹配。

> 残留风险：预检弹窗的**存在性**与**「否」= 中止整个保存**未经运行验证；若判反，最坏是"多问一句/少问一句"，不损坏数据。

## 问题反馈

### 问题1：ready 超时后未回退，只弹了「界面未能加载」气泡（第一轮）
- [x] 已解决（诊断为测试前置未满足 + 引出一次设计改进）

**现象**：`DebugEnabled` 按前置应为 0，实际超时后没有回落经典界面，只弹了「界面未能加载…」气泡。
**根因（已用证据查实，非代码缺陷）**：
- `Settings.ini` 实际为 `DebugEnabled=1`、`UiEngine=web`；
- 日志 `00:58:04.788 [WebHost] web 引擎已就绪` → 预检通过；`00:58:13.394 [WARN] [WebHost] 界面未在 8000 ms 内上报 ready` → 超时命中；**但没有** `web 引擎回落经典界面` 行。
- 即代码按约定走了「`DebugEnabled=1` → 保留窗口」分支，行为符合设计；是前置条件没被实证。

**由此暴露的设计软肋（已修）**：`DebugEnabled` 是开发者会长期开着的开关，所以「保留窗口」分支在开发期反而是常态，于是「页面挂掉＝死路一条」也是常态（无设置界面、托盘也无引擎项）。已改为：该分支先弹确认「界面未能加载。是否回退到经典界面？选择「否」可保留当前窗口以便排查。」——选「否」才保留窗口，选「是」走 `_Fallback()`。本流程已补上「点否」「点是」两条验证项。
