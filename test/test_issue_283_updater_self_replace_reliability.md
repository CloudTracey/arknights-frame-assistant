## 集成测试

### 流程：正常自动更新（zh-Hans 中文系统）

> 涉及模块：`updater_manager.ahk`、`self_replacer.ahk`、`Run` 批处理、`LogExporter`

- [ ] **前置**：语言为简体中文；AFA 版本落后于仓库最新版本（或使用任意便于验证的模拟流程）。
- [ ] **操作**：在更新提示中确认更新，等待下载完成后进入自替换。
- [ ] **预期**：更新 cmd 窗口标题为「AFA更新中...」；控制台输出中文（含「正在等待程序关闭...」及求饶彩蛋），**无** `is not recognized` / `'�我'` 类乱码报错。
- [ ] **预期**：AFA 退出后 1~3 秒内，update 日志出现 `程序已关闭 - PID <pid>`；随后「正在替换文件...」→「替换成功！」→「正在启动新版本...」→「新版本已启动」→「更新流程结束」。
- [ ] **预期**：新版本 AFA 正常启动；`%TEMP%\ArknightsFrameAssistant` 中 `update_replacer.bat`、`update_replacer_text.bat`、备份文件与更新文件均被清理（目录为空或被删除）。
- [ ] **操作**：查看 `%AppData%\ArknightsFrameAssistant\PC\logs\update-*.log`。
- [ ] **预期**：日志为 UTF-8、无乱码；首行带 `[2026-xx-xx xx:xx:xx] 开始更新流程`；进程行含精确 PID。

### 流程：等待超时路径

- [ ] **前置**：确认更新进入自替换后，立即再启动一个旧版 AFA.exe 实例挡住等待（或用其它方式保持旧 PID 存活 >10s）。
- [ ] **操作**：观察更新窗口与 update 日志。
- [ ] **预期**：约 5 秒出现心跳行 `!MSG_WAITING! - PID <pid>, 5s`；约 10 秒出现 `等待超时，继续尝试...` 后**仍继续尝试替换**（不卡死）。

### 流程：失败还原路径

- [ ] **前置**：将下载好的更新文件（新 exe）删除或写坏后再确认更新（模拟"新文件被安全软件删除/损坏"）。
- [ ] **操作**：确认更新并观察。
- [ ] **预期**：等待退出后进入 `cleanup_failed`：日志出现「替换失败，正在尝试自动还原原文件...」，随后「原文件已还原」；窗口 `pause` 停留显示失败原因与新/备份文件位置；按任意键后关闭，两个批处理文件被删除，**原 AFA.exe 与备份文件保留**（可据提示手动恢复）。

### 流程：文案子脚本缺失（英文默认值兜底）

- [ ] **前置**：语言为 zh-Hans；触发更新确认前，手动删除 `%TEMP%\ArknightsFrameAssistant\update_replacer_text.bat`（或触发一次生成后立即删除）。
- [ ] **操作**：确认更新并观察控制台 / update 日志。
- [ ] **预期**：批处理以英文默认文案完整走完流程（Waiting for AFA to exit... / Replacement successful / Update finished），无报错；替换与清理正常。

### 流程：ja-JP / ko-KR / en-US 语言

- [ ] **前置**：在设置中将语言切换为 en-US（或 ja-JP / ko-KR）并应用，重启 AFA。
- [ ] **操作**：确认更新进入自替换。
- [ ] **预期**：控制台与 update 日志均为英文文案（仅生成主脚本，不生成 `update_replacer_text.bat`）；流程完整无报错。

##### 异常路径

- [ ] **异常**：新版本启动后立即再启动一次自动更新（连续更新）→ **预期**：`CleanupAll`/新会话能正常重建两个批处理文件，无残留 `update_replacer_text.bat` 干扰下一轮。
- [ ] **异常**：`%TEMP%` 路径包含中文用户名 → **预期**：控制台与日志无乱码（路径按 UTF-8 解析正确）。
