### 功能点：关卡外透传大小写（CapsLock）

> 背景：游戏内技能键默认 `e`，AFA「一键技能」默认也是 `e`，`e` 同时命中拦截正则——关卡外按 `e` 会被拦截并透传。修复前大写锁定开着也输入小写，修复后应与物理按键一致。

- [x] **前置**：游戏运行且 AFA 以管理员运行；关卡外（主界面/基建等非关卡界面，游戏窗口为活动窗口）；游戏内技能键 = `e`，AFA「一键技能」= `e`（默认配置即可）。
- [x] **操作**：关闭大写锁定，在游戏窗口内按下 `e` 再松开（该键被 AFA 拦截并透传）。
- [x] **预期**：游戏内无异常表现；`e` 被正常透传（无卡键、无重复输入）。
- [x] **操作**：打开大写锁定，在游戏窗口内按下 `e` 再松开。
- [x] **预期**：透传输入的字符与物理按键一致（大写 `E`）——需在游戏内可输入文本的场景观察（如登录/昵称/签名输入框；若当前无文本输入点，请将「输入字符大小写」改在游戏外对照验证并在备注说明）。
- [x] **操作**：对照验证——在游戏外（如记事本）开启大写锁定，按 `e`。
- [x] **预期**：记事本输入 `E`（AFA 不拦截游戏外按键，行为不变）。

### 功能点：关卡外透传与修饰键（Shift）

- [x] **前置**：同上一功能点（游戏窗口活动、关卡外）；若有游戏内文本输入场景则用它，否则以游戏外对照为准。
- [x] **操作**：在游戏窗口内按住 `Shift` 同时按 `e` 再松开。
- [x] **预期**：透传入游戏的按键带修饰状态（字符为大写 `E`，与物理按键一致），且松开后 `Shift`/`e` 无卡键。
- [x] **操作**：为对照，在记事本（游戏外）按住 `Shift` 按 `e`。
- [x] **预期**：输入 `E`，无异常。

### 功能点：同帧竞态（一键技能）

> 背景：关卡内按 `e` → AFA 注入完整 `e` 按下/松开给游戏；若物理松开触发的透传 Up 与注入 Down 落在同一画面帧，游戏帧开头轮询只读到 Up，技能不释放（原缺陷表现为「左键选中干员但技能未开出」）。修复后 Up 变体在注入按下未完成时抑制补发。

- [x] **前置**：进入任意关卡；游戏内技能键 = `e`；AFA「一键技能」= `e`；鼠标在游戏窗口内。
- [x] **操作**：关卡内**快速按放** `e`（按下后立即松开，模拟人速；重复 20 次以上，故意在按下的 100~300ms 内快速放掉）。
- [x] **预期**：每一次按 `e`：先左键选中不占用技能释放（左键点击），随后技能稳定释放（干员技能亮起并施放），**不再出现**「只有左键选中、技能未释放」。
- [x] **操作**：可选——开启 AFA 调试日志（调试控制台/日志文件），反复快速按放 `e`，观察关键字 `抑制透传 Up：key=e`。
- [x] **预期**：至少出现过一次抑制日志（说明命中抑制路径）；技能每次都释放。

### 功能点：同帧竞态（一键撤退 / 暂停技能 / 暂停撤退）

> 与一键技能同机理（`Tap` 与 `SendDown/SendUp` 注入窗口），按键按用户实际配置调整。

- [x] **前置**：进入任意关卡；游戏内撤退键 = AFA「一键撤退」键（默认二者均为 `q`）；鼠标在游戏窗口内。
- [x] **操作**：关卡内快速按放撤退键（20 次以上），每次目标干员依次放置并撤退。
- [x] **预期**：每次撤退指令稳定生效（干员逐个撤下），无「已选中但未撤退」。
- [x] **操作**：将 AFA「暂停技能」绑定 = 游戏内技能键 `e`（或保持默认 XButton2 = 游戏内鼠标前进键），关卡内快速按放触发暂停技能。
- [x] **预期**：暂停技能稳定触发（选中干员 → 技能一帧后暂停效果正常），无仅选中无施放。

### 功能点：透传与胶囊/句柄类按钮键（滚轮）

- [x] **前置**：AFA 任一守卫热键绑定滚轮（如「技能」绑定 `WheelUp`），游戏内技能键 = `e`；关卡外、游戏窗口活动。
- [x] **操作**：滚动鼠标滚轮（向上）一次。
- [x] **预期**：滚轮事件被透传给游戏且无异常（无重复/无丢失），游戏内无其他按键被错误触发。

## 集成测试

### 流程：守卫放行/拦截两路径的按键流向（e 键）

> 涉及模块：`LevelDetector`、`GuardInLevel`、`KeyForward.ForwardOriginalKey/ActionUpForward`、`GameKeys.Tap`

- [x] **前置**：游戏内技能键 = `e`，AFA「一键技能」= `e`（默认）；关卡守卫开启（InLevelGuard=1）。
- [x] **操作**：在关卡内按放 `e`。
- [x] **预期**：动作放行 → AFA 注入 `e` 按下/松开 → 技能释放；注入按下未完成时物理松开被抑制（无同帧补发）。
- [x] **操作**：退出关卡回到主界面/基建（LevelDetector 判定不在关卡），再按放 `e`。
- [x] **预期**：守卫拦截 → 透传 down/up 补发，游戏收到完整的 `e` 按下/松开（无卡键）。
- [x] **操作**：关卡内按住 `e` 拖出游戏窗口外再松开；以及关卡内按住 `e` 后 Alt+Tab 切走再松开。
- [x] **预期**：松开后游戏内无卡键（`e` 不粘滞）；回游戏后按键行为正常（失焦/拖出卡键修复不回归——注意注入路径下该松开被抑制属预期，观察「后续按下仍正常」）。

### 流程：命中场景与未命中场景

- [x] **前置**：游戏内技能键改为 `j`（游戏设置内改键，10 秒内由 AFA 轮询重建热键）；AFA「一键技能」= `e`。
- [x] **操作**：关卡内快速按放 `e`。
- [x] **预期**：一键技能正常释放（注入 `j` 给游戏）；因 `e` 不再是游戏键，`e` 不命中拦截正则（`~` 前缀透传），物理 `e` 直接进游戏——关注是否出现重复/冲突（应无）。
- [x] **操作**：关卡外快速按放 `e`。
- [x] **预期**：动作被守卫拦截 → 透传 `e`（游戏键已改，`e` 现在不拦截，物理 `e` 自然透传），无异常。

### 流程：<<SHIFT 倍速热键（修饰键卡死回归）

- [x] **前置**：AFA「切换倍速」绑定 `<SHIFT`（左 Shift）；游戏内倍速键 = `f`（默认）；关卡内。
- [x] **操作**：关卡内按下左 Shift（触发切倍速）并观察松开。
- [x] **预期**：倍速切换生效；松开后游戏内/系统级 Shift 均不卡住（后续可正常选中干员、正常键盘操作，如按 `Shift` 移动不粘滞）。
- [x] **操作**：关卡外按左 Shift（守卫拦截路径）。
- [x] **预期**：透传 down/up 均补发，无卡键；AFA 界面（若有 Shift 快捷键）不受影响。

##### 异常路径

- [x] **异常**：关卡内按住 `e` 期间游戏窗口失焦（Alt+Tab/拖出），随后关卡检测状态翻转（如从关卡内变为关卡外）再松开 → **预期**：无卡键、无重复补发，按键状态最终平衡。
- [x] **异常**：快速连按被拦截键（如 `e` 连打 5 次）→ **预期**：每次按下都能触发一次动作；无按键粘滞、无丢失（已透传 down 的按住周期内 key repeat 不重复透传）。

## 回归测试

### 功能：关卡守卫开关

- [x] 验证：关闭「关卡守卫」（InLevelGuard=0）后，关卡外按被拦截键直接放行（AFA 功能直接触发，不再透传），行为与关闭前不同但无异常；重新开启后守卫恢复。

### 功能：未拦截键 / 普通打字

- [x] 验证：关卡内+关卡外按未被拦截的字母（如 `a`、`w`）与数字键，字符输入大小写随物理状态（大写锁定/Shift 行为与系统一致），无被改写、无卡键（Issue #240 a/A 透传回归）。

### 功能：Up 型热键（松开暂停 Space）

- [x] 验证：「松开时暂停」绑定 Space 时：按下不触发、松开触发；游戏内暂停键 `Space` 的注入与物理不冲突（无卡键、无重复）。

### 功能：鼠标键拦截（RButton/MButton）

- [x] 验证：绑定在 `RButton`/`MButton` 的 AFA 热键：游戏窗口外点击不被拦截（透传给系统），窗口内点击行为不变。

### 功能：自动开局暂停（GameMonitor 注入 pauseBattle）

- [x] 验证：进入关卡自动暂停功能正常（注入 `Space` 按下/松开）；物理按放 Space 与自动暂停无相互干扰。

### 功能：自定义 combat 类型按键

- [x] 验证：自定义按钮类型「作战」（受守卫）绑定被拦截键：关卡外拦截透传、关卡内直接执行，行为与内置守卫热键一致。
