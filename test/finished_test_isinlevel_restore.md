# 测试清单：`isinlevel_restore`

> 对应更改：为常规作战全部 14 个功能恢复关卡界面检测（IsInLevel）守卫（12 恢复 + 2 新增），守卫拦截时写 Warn 日志并**事件驱动透传原键**（按下补发 key down，Up 变体热键补发 key up，无 KeyWait 阻塞、多键并发正确）；14 个函数统一 per-monitor DPI 上下文；`hotkey_control.ahk` 为 13 个守卫键注册 Up 变体（`ActionUpForward` 回调）

## 测试环境

| 项目 | 信息 |
|------|------|
| AFA 版本 | `v1.5.12` |
| AutoHotkey 版本 | `v2.0.26` |
| Windows 版本 | `Windows 11 25H2` |
| 测试日期 | `2026-08-01` |

### 流程二：关卡外全部拦截 + 原键透传

> 涉及模块：`hotkey_actions.ahk`、`logger.ahk`（新增 `ForwardOriginalKey` 透传）

**前置**：游戏处于非关卡界面（如主界面/基建/肉鸽菜单/剧情界面）

- [x] **操作**：在主界面依次按下上述 14 个热键（按下暂停/松开暂停/切换倍速/过帧×3/单位技能/单位撤退/暂停选中/一键技能/一键撤退/暂停技能/暂停撤退/视角切换）
- [x] **预期**：AFA 功能全部不执行（无暂停/过帧/点击等动作）
- [x] **预期**：原键**透传**给游戏——游戏内表现为"没有 AFA 热键"时的原生行为（如 W 在游戏内绑定功能则会正常触发）
- [x] **预期**：`%AppData%\ArknightsFrameAssistant\PC\logs\` 日志中出现对应 Warn 记录（形如 `ActionPressPause 被关卡检测拦截（不在关卡界面）`），14 个函数名一一对应
- [x] **操作**：按住某热键（如 W）不放再松开 → **预期**：游戏收到 key down + key up 完整状态流（按住/松开表现与无 AFA 一致），且不重复透传
- [x] **操作**：多键并发——按住 A 不松开再按 D（两个都是热键），先松开 A → **预期**：A 正常松开，D **保持按下**（不联动松开）；再按 A → **预期**：A 正常按下（不失效）；再松开 D → **预期**：D 正常松开（无错位、无延迟补发）
- [x] **操作**：绑滚轮（WheelUp）为热键后关卡外滚动 → **预期**：游戏收到一次完整滚轮事件
- [x] **操作**：绑定带修饰符的组合键（如 Ctrl+W）后关卡外按下 → **预期**：游戏收到 Ctrl（自然透传）+ W（守卫补发）的完整组合

##### 异常路径

- [x] **异常**：关卡外按键产生拦截日志是预期行为 → **预期**：Warn 日志不触发任何弹窗或崩溃

## 追加测试：KeyForward 封装回归（2026-08-01）

> 对应更改：透传状态与行为封装为 `KeyForward` 类（`InterceptedKeys` 静态成员 + `PureKeyName`/`ForwardOriginalKey`/`ActionUpForward` 静态方法），消除裸全局变量与自由函数耦合；调用点改为 `KeyForward.` 前缀（`GuardInLevel`/`PureKeyWait`/`hotkey_control._RegisterOne`）。行为零变化，纯封装重构

### KeyForward 封装回归

- [x] 验证：AFA 启动正常（`KeyForward` 类定义无语法错误，热键全部注册成功）
- [x] 验证：关卡内按热键 → 功能正常（守卫放行路径不受封装影响）
- [x] 验证：关卡外按热键 → 拦截 + 透传正常（down 补发、松开 up 补发——`KeyForward.InterceptedKeys` 标志读写正常）

- [x] 验证：松开暂停（ReleasePause）关卡内松开触发、关卡外拦截透传（Up 变体注册引用 `KeyForward.ActionUpForward` 正常）
