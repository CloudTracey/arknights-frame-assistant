# 测试清单：鼠标热键窗口外拦截修复（HotkeyContext 悬停判定）

> 对应更改：将 `hotkey_control.ahk` 的热键判定从 `HotIfWinActive("ahk_exe Arknights.exe")` 改为 `HotIf(HotkeyContext)` 回调。`HotkeyContext` 逻辑：① Up 变体优先查 `KeyForward.InterceptedKeys` 状态——down 已被 AFA 拦截补发则无条件放行补发 key up（解决"按住拖出窗口/Alt+Tab 切走再松开"卡键，含上次遗留的失焦边界）；② 鼠标键/滚轮（LButton/RButton/MButton/XButton1/XButton2/Wheel*）返回 `IsMouseInClient()`——鼠标悬停在游戏窗口上才触发，窗口外点击透传给系统（任务栏/桌面菜单可正常弹出）；③ 键盘键返回 `WinActive("ahk_exe Arknights.exe")`（维持原行为）。替换了全部 6 处 `HotIfWinActive`（注册与注销同上下文）。另含 `hotkey_actions.ahk` 已有改动：删除 16ms/33ms/166ms 过帧的 `IsMouseInClient` 检查（过帧不再要求鼠标在游戏内）。

## 问题反馈

### 问题1：关卡外按住 w 等被拦截键，拦截日志刷屏（切换窗口时 key repeat 触发）

> 现象：游戏内关卡外**按住 w 只记 1 次**；**按住 w 然后 Alt+Tab 切换窗口**时才连续刷屏记录

- [x] **已分析**：AHK 热键默认抑制 key repeat（游戏内按住只触发一次）；切走（Alt+Tab/焦点变化）重置抑制状态 → repeat 重新触发主热键 → `GuardInLevel` 每次拦截都记日志。`ForwardOriginalKey` 有重复 down 去重，但**日志在补发之后无条件记录**。**既有行为，非本次改动引入**
- [x] **已修复**：`GuardInLevel` 拦截日志去重——同一按住周期（`InterceptedKeys` 已记录 down 已补发）的重复拦截不再记日志，仅首次记录；滚轮逐条保留
- [x] **已验证通过**：按住 w 切走不再刷屏（仅首次记录），松开后再按仍记录新一次

### 问题2：失焦边界未解决（流程 5）——关卡内（守卫放行路径）按住 Shift 切走松开仍卡键

> 现象：进关卡按住左 Shift → Alt+Tab 切走 → 其它窗口松开 → 切回，Shift 仍被 OS 视为按住

- [x] **已定位根因**：Up 变体放行原先依赖 `InterceptedKeys`，但它只在**守卫拦截路径**（关卡外，`ForwardOriginalKey` 补发 down）写入；**守卫放行路径**（关卡内，动作直接执行）不写 → 失焦松开时 Up 变体不放行 → 不补发 up → OS 层修饰键状态卡住
- [x] **已修正**：改用静态 `KeyForward.GuardedUpKeys` 标记守卫 Up 变体，`HotkeyContext` 对 Up 变体命中即**无条件放行**补发 up（对未按下的键是无害 no-op）；OnUp 功能型（ReleasePause）不在该集合，不受影响
- [x] **已重测通过**（流程 5 通过）——注：该"无条件放行"随后引入了 Up 变体递归循环问题，见问题 3

### 问题3：游戏外 AFA 绑定键失灵（GuardedUpKeys 引入 Up 变体无限递归循环）

> 现象：游戏没打开，AFA 存在时，a/w 等守卫绑定键在游戏外按下无任何反应（无法打字）；游戏内正常

- [x] **已定位根因**：`GuardedUpKeys` 静态标记使 Up 变体无条件放行；`ActionUpForward` 的 Send 补发 up 被钩子重新捕获 → 再次触发 Up 变体 → 无限循环补发 → 系统键盘状态被轰炸、AHK 线程风暴 → 按键失灵。第一版（InterceptedKeys）因补发后清除记录而无此问题
- [x] **已修复（第二轮）**：诊断日志确认根因是 `GuardedUpKeys` **静态标记**在游戏外也放行 Up 变体——游戏外主热键不触发（down 透传）时，松开守卫键仍触发 Up 变体吞 up + Send 补发 → 打字字符异常失灵。改用运行时 `KeyForward.DownHandled`（**主热键触发即记录**，无论守卫放行/拦截）替代静态标记：游戏外不放行（物理 up 透传，打字正常），主热键处理过才放行补发 up（保住失焦/拖出）；保留 `SuppressUp` 防 Send 注入递归
- [x] **已重测通过**：①游戏外打字恢复正常 ②游戏内功能正常 ③失焦边界通过 ④鼠标拖出通过
