## 集成测试

### 流程：开启调试模式后自动更新

> 涉及模块：`base/logger.ahk`（SetConsoleEnabled/CloseConsole）、`core/updater/self_replacer.ahk`、`updater_manager.ahk`

- [ ] **前置**：设置 → 其他设置 → 日志 → 勾选「启用调试模式」并应用；观察「AFA 调试日志」控制台窗口已打开（亮蓝横幅 + 回放日志）。
- [ ] **操作**：确认更新并进入自替换步骤，观察更新 cmd 窗口。
- [ ] **预期**：更新 cmd 窗口内**只**显示批处理自身输出（Waiting for AFA to exit... / 替换相关文案），**不再出现** `[Shutdown] 程序退出 reason=...` 或任何 AFA 日志行。
- [ ] **操作**：检查 AFA 旧进程是否自行退出、新版本是否启动。
- [ ] **预期**：更新流程完整：替换成功 → 新版本启动 → 更新日志 `update-*.log` 完整记录。

### 流程：新版本调试控制台恢复

- [ ] **前置**：完成上一流程后，新版本 AFA 已启动且配置仍为「启用调试模式」。
- [ ] **操作**：观察新版本窗口。
- [ ] **预期**：「AFA 调试日志」控制台按配置**重新打开**（新的独立控制台窗口）。

### 流程：未开启调试模式

- [ ] **前置**：配置为关闭调试模式，重启 AFA（无调试控制台）。
- [ ] **操作**：确认更新进入自替换。
- [ ] **预期**：更新窗口行为与修复前完全一致（批处理正常执行、日志完整），渲染无变化。

##### 异常路径

- [ ] **异常**：更新批处理启动失败（如被安全软件实时拦截删除、临时目录权限异常触发 `Run` 抛错）→ **预期**：AFA **不退出**，弹「启动替换脚本失败」消息框，且「AFA 调试日志」控制台**恢复打开**（用户不丢失实时日志）；普通日志记录 Error。
