## 问题反馈

### 问题1（测试 7）：右列"顶部标签页"整体偏下
- 复现：打开"其他设置 → 自定义"。
- 现象：左列错位已修复（左列恢复到正确位置，与其他分类对齐），但**右列"顶部标签页"整体偏下**，与左列不在同一水平线——此前因左列整体下移掩盖了此问题。
- 推断：右列 `tabManagerTitle` 使用 `y72` 绝对坐标，而左列内容顶部在 `y48 + 10 = y58` 左右，两者差约 14px。
- 修复：`txtClickDelay` 创建后 `GetPos` 读取实际 y 存入 `TabManagerTitleY`，右列标题动态对齐（标题→提示 20px，提示→首行 43px 固定间距），`TabManagerRowStartY` 同步动态化。避免绝对坐标估算误差。
- [x] 已解决

### 问题2（测试 8）：拖拽时前一行高亮背景残留
- 复现：拖动一个标签行（产生强调色背景高亮），松开后再拖动**另一个**标签行。
- 现象：前一个标签行的强调色背景不会立即消失；只有拖动位置经过前一个标签行原所在的位置时，高亮才消失。
- 根因（深挖）：AHK 对 Text 控件**运行时用 `Opt("Background" color)` 改背景色不可靠**——文档明确"the control might choose to ignore it"。高亮能显示但取消高亮不刷新，`Sleep -1`/`Redraw()` 均无法绕过。
- 修复（双控件叠加）：每行新增 `RowHighlight`（EAF2FB 高亮层，初始隐藏），与 `RowBackground`（固定 F5F7FA）同位置叠放。`RenderTabManager` 通过 `RowHighlight.Visible := (index = TabDragIndex)` 切换，不再用 `Opt` 改色。`GetTabManagerHit` 同步纳入高亮层命中。
- 补充修复：`_SwitchOtherCategory("Custom")` 遍历显示 CustomControls 会把 `RowHighlight` 一并设为可见，导致启动后切换分类时全部标签误高亮。在显示后调用 `RenderTabManager()` 重置高亮为 `TabDragIndex` 决定的状态。
- [x] 已解决

### 问题5：眼睛图标/控件区域与拖动图标大小不一致
- 现象（最终确认）：偏大的不是眼睛字形，而是**眼睛所在控件区域（白色方框）比拖动/标签的更高**。字形实测高度三者几乎一致（雅黑 s9 与 MDL2 s11 均约 16.5-16.7px）。
- 根因：三个子控件创建时 y 偏移不一致（拖动 +4、标签 +5、眼睛 +3）且眼睛原尺寸 w30 h20（其他为 h18），底边/中心线错位，眼睛区域视觉偏高。
- 修复：眼睛字号 s12→s11（避免 s9 过小）；三个子控件 y 统一为 `rowY+4`、高度统一 h18，创建与渲染处同步；眼睛尺寸 w24 h18。
- [x] 已解决

### 问题3（测试 9）：U+E9CE 渲染为"圆+问号"（字形缺失）
- 复现：点击标签眼睛图标隐藏后，隐藏图标显示为"圆中间一个问号"的占位图形（颜色正确为灰色）。
- 现象：`U+E9CE` 在当前系统（Windows 11 25H2）的 Segoe MDL2 Assets 字体中**字形缺失**，AHK 以问号替代显示。
- 修复：按用户建议改为**统一用 `U+E890`（睁眼，MDL2 中确定存在）**，用颜色区分状态：蓝（`c1994d2`）=显示、灰（`cA0A0A0`）=隐藏。与 `ManagerLabel` 的颜色区分方式一致，不再依赖不存在的"闭眼"字形。
- [x] 已解决

### 问题4（测试 10）：隐藏最后一个功能标签的保护未生效
- 复现：隐藏"常规作战"和"快捷操作"（**未应用**），再点击"卫戍协议"的眼睛图标。
- 现象："卫戍协议"仍被隐藏——保护逻辑未生效。
- 根因（已定位）：`_CountVisibleFunctionalTabs()` 用 `IsTabVisible()` 计数，而 `IsTabVisible` **优先读 `AppliedTabSettings.Visibility`**（已应用快照）而非 `tabItem.Visible`（工作态）。未应用时计数读到旧状态（仍=3）。
- 期望交互（用户提出）：隐藏最后一个功能标签时**弹出提示窗口**"至少保留一个功能标签页"。
- 修复：`_CountVisibleFunctionalTabs` 改为直接遍历 `tabItem.Visible`（工作态）计数；保护触发时 `MessageBox.Info` 弹窗且不执行隐藏。
- [x] 已解决
