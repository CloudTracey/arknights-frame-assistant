# 测试清单：`hover_operate_one_shot_reset`

> 对应更改：新增 `[OneShot] HoverOperateReset` 一次性迁移，升级后首次启动把 `[Custom] HoverOperate` 写回 `0`；状态栏说明标注该开关只影响键盘热键；勾选开关时增加一次风险确认弹窗。

## 测试环境

| 项目 | 信息 |
|------|------|
| AFA 版本 | `v2.3.2`（分支 `fix/hover-operate-one-shot-reset`，本次未提升版本号） |
| AutoHotkey 版本 | `v2.0.26` |
| Windows 版本 | `Windows 11 10.0.26300.9974` |
| 测试日期 | `2026-11-17` |

> 涉及改写 `Settings.ini` 的用例，请先完全退出 AFA（含托盘图标），并备份 `%AppData%\ArknightsFrameAssistant\PC\Settings.ini`；测试结束后按需恢复。全新安装用例需要临时移走该文件，恢复备份前不要覆盖备份。

## 单元测试

### 功能点：升级老配置时执行一次性迁移

- [x] **操作**：关闭 AFA，备份并打开 `%AppData%\ArknightsFrameAssistant\PC\Settings.ini`，确认 `[Custom]` 下 `HoverOperate=1`；若不存在 `[OneShot]` 键则无需处理，若存在则删除 `HoverOperateReset`。
- [x] **预期**：配置处于“旧版默认开启 + 无一次性标记”的初始状态。
- [x] **操作**：启动 AFA，等待启动完成，再次打开 `Settings.ini`。
- [x] **预期**：`[Custom]` 下 `HoverOperate=0`；`[OneShot]` 下出现 `HoverOperateReset=1`。
- [x] **操作**：打开设置窗口，进入「其他设置 → 自定义」，观察复选框和底部按钮。
- [x] **预期**：复选框未勾选；未做其他修改时「保存并关闭」「应用设置」不可用，且不出现「修改尚未保存或应用」提示。
- [x] **操作**：查看 AFA 日志（「日志」页打开日志目录，或打开调试控制台）。
- [x] **预期**：有 Info 日志「已一次性关闭失焦悬停热键（原值 1）」。

### 功能点：原本已是关闭状态的配置也会写标记

- [x] **操作**：关闭 AFA，把 `Settings.ini` 中 `[Custom] HoverOperate` 改为 `0`，删除 `[OneShot] HoverOperateReset`，启动 AFA。
- [x] **预期**：`HoverOperate` 保持 `0`，`[OneShot] HoverOperateReset=1` 被写入；复选框未勾选，无脏状态。

### 功能点：全新安装首启也写标记

- [x] **操作**：关闭 AFA，把 `Settings.ini` 移出配置目录（例如改名为 `Settings.ini.bak-manual`），启动 AFA。

- [x] **操作**：退出 AFA，恢复刚才移走的 `Settings.ini`。
- [x] **预期**：恢复后的配置可正常加载，AFA 启动无异常。

### 功能点：标记只生效一次，不覆盖用户重新开启

- [x] **操作**：完成迁移后，在「其他设置 → 自定义」勾选复选框，确认弹窗选「是」，点击「保存并关闭」。
- [x] **预期**：`Settings.ini` 中 `HoverOperate=1`，`[OneShot] HoverOperateReset=1` 仍在。
- [x] **操作**：重启 AFA，打开设置查看复选框。
- [x] **预期**：复选框保持勾选，配置仍为 `1`，不会被再次重置。

### 功能点：勾选风险确认弹窗

## 集成测试

### 流程 1：原始问题复现路径（升级后不再误触发）

> 涉及模块：`config.ahk`、`settings_service.ahk`、`hotkey_service.ahk`、`gui.ahk`

- [x] **前置**：已完成一次性迁移（`HoverOperate=0`）；游戏以窗口化运行；在「常规作战」页绑定一个键盘热键（如「撤退」= Q）；打开 QQ 或记事本并置于前台，调整窗口大小让鼠标位置下的游戏窗口仍然可见（不要被前台窗口完全遮住）。
- [x] **操作**：鼠标保持在游戏窗口可见区域上，在 QQ/记事本中按下绑定的键盘热键。
- [x] **预期**：AFA 动作不触发；游戏窗口不会被激活到前台；按键正常输入到 QQ/记事本。

### 流程 2：游戏在前台时功能正常

- [x] **前置**：`HoverOperate=0`，游戏在前台，绑定的键盘热键可用。
- [x] **操作**：按下绑定的键盘热键。
- [x] **预期**：对应 AFA 动作正常执行。

### 流程 3：用户重新开启后恢复失焦悬停触发

- [x] **前置**：`HoverOperate=0`，游戏失焦，鼠标悬停在游戏窗口可见区域。
- [x] **操作**：打开设置 → 自定义 → 勾选开关 → 确认「是」→ 点击「应用设置」；回到游戏失焦、鼠标悬停状态，按绑定的键盘热键。
- [x] **预期**：AFA 动作正常触发，游戏窗口被激活（#213 原有行为恢复）。

### 流程 4：鼠标键/滚轮路径不受本开关影响

> 涉及模块：`hotkey_service.ahk`（`HotkeyContext` 的鼠标键分支）

- [x] **前置**：`HoverOperate=0`；将一个鼠标侧键（如 XButton2）绑定到某个动作；游戏失焦，鼠标悬停在游戏窗口可见区域。
- [x] **操作**：按下该鼠标侧键。
- [x] **预期**：动作仍然触发（鼠标键只受悬停判定，不受 HoverOperate 开关控制）。
- [x] **操作**：把鼠标移到游戏窗口外（如桌面/任务栏），再按该侧键。
- [x] **预期**：动作不触发，鼠标点击正常透传。

### 流程 5：保存 / 应用 / 取消生命周期

- [x] **前置**：`HoverOperate=0`，游戏失焦，鼠标悬停游戏窗口，按绑定键盘热键不触发。
- [x] **操作**：勾选开关，确认「是」，点击「应用设置」，再次按该键。
- [x] **预期**：开关立即生效，动作触发。
- [x] **操作**：取消勾选（不弹确认），点击「应用设置」，再次按该键。
- [x] **预期**：开关立即关闭，动作不触发、游戏不被激活。
- [x] **操作**：勾选开关，确认「是」，点击「取消」。
- [x] **预期**：配置保持未开启；再次按该键不触发。

### 流程 6：异常路径——INI 写入失败时保留原值并重试

- [x] **异常**：关闭 AFA；把 `Settings.ini` 的 `HoverOperate` 改为 `1`，删除 `[OneShot] HoverOperateReset`；给 `Settings.ini` 加只读属性（`attrib +R`）；启动 AFA。
- [x] **预期**：AFA 正常启动，不崩溃；日志出现 Warn「一次性关闭失焦悬停热键失败，下次启动重试」；`Settings.ini` 的 `HoverOperate` 仍为 `1`，复选框勾选。
- [x] **恢复**：退出 AFA，去掉只读属性（`attrib -R`），重新启动 AFA。
- [x] **预期**：本次成功迁移，`HoverOperate=0`、`HoverOperateReset=1`。
- [x] **备注**：若当前环境以管理员运行后仍能写入只读文件，记录实际结果并标注本项不适用。

### 流程 7：四语言确认弹窗

- [x] **操作**：切换界面语言为 zh-Hant / ja-JP / ko-KR / en-US，在每种语言下打开设置并点击复选框（若每次都选「否」，可在同一运行内连续测试；若中途选过「是」，需重启 AFA 重置“本次运行已确认”状态）。
- [x] **预期**：确认框标题、正文、按钮文字均为当前语言，文本自动换行、不溢出窗口；选择「否」后复选框回退为未勾选。
